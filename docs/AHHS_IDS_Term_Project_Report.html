4. Abstract

Modern high-speed network fabrics (10 Gbps, 40 Gbps, 100 Gbps) and dense multi-tenant cloud environments have rendered traditional user-space Intrusion Detection and Prevention Systems (IDS/IPS), such as Snort and Suricata, severe throughput and latency bottlenecks. Operating across user-space boundaries requires per-packet kernel socket buffer allocations (sk_buff), context switching, and PCIe memory copies, incurring millisecond-scale detection lags and catastrophic packet drops under volumetric network floods. While in-kernel packet inspection via Extended Berkeley Packet Filter (eBPF) and the eXpress Data Path (XDP) offers execution directly inside the network interface driver receive (RX) hook, existing in-kernel IDSes face an empirical trilemma: static in-kernel rule filters operate at wire speed but offer 0% zero-day or behavioral anomaly detection; monolithic per-packet neural networks evaluate floating-point or heavy matrix arithmetic on every packet, collapsing single-core forwarding throughput to ~1.2 Mpps (>95% packet drops at line rate); and hybrid ring-buffer offload architectures incur a 5–50 ms userspace synchronization delay during which over 300,000 malicious packets breach the protected host.

To resolve these critical bottlenecks, this term project implements and evaluates the Adaptive Hybrid Hardware-Software Intrusion Detection System (AHHS-IDS). AHHS-IDS introduces a three-tiered hierarchical security architecture entirely inside the Linux kernel data path: Tier 1 executes a branchless, verifier-safe decision tree in 11.8 ns at driver ingress, resolving ~90% of known benign and malicious traffic; Tier 2 tracks dynamic connection states for ambiguous flows across an eBPF Least Recently Used (LRU) hash map (65,536 entries), aggregating running statistics over sliding windows of 100 packets or 1.0 second, eliminating persistent connection blind spots; and Tier 3 executes a 4-program chained, integer-quantized neural autoencoder ($8 \to 16 \to 4 \to 16 \to 8$, 428 parameters, 592 bytes) via tail calls without floating-point hardware. Triggered once per 100 packets, deep inference is amortized to an empirical 3.42 ns per ambiguous packet. Offending flows exceeding a calibrated anomaly threshold ($\theta=58$) are immediately written to an in-kernel blocklist map (`ahhs_blocklist`) with a 60-second TTL in under 1 μs, dropping subsequent attack packets in ~12 ns at Tier 1 ingress.

The entire system was implemented, trained, and benchmarked on 12,100 held-out flow windows (1,210,000 packets) from the official Canadian Institute for Cybersecurity (CIC-IDS-2017) dataset. AHHS-IDS achieved an overall multi-tier detection rate of 85.07% (100.00% on Friday PortScan, 70.14% on Wednesday DoS Slowloris) with a multi-tier ROC-AUC of 0.9567 and 9.81% false alarms on held-out benign traffic. Across real kernel benchmarks on Linux Kernel 6.8, AHHS-IDS achieved a single-core throughput of 60.7 Mpps (a $50.6\times$ improvement over monolithic kernel ML) with an amortized per-packet latency of 16.45 ns, an in-kernel memory footprint of 7.2 MB (100% CPU L3 cache resident), under 600 total BPF instructions across 4 tail calls, and 100.0% bit-exact parity across 240 golden trace vectors.

5. Introduction Containing Literature Survey

The explosive growth of cloud data centers, edge computing clusters, and high-bandwidth interconnects has elevated network line rates from gigabit to 10G, 40G, and 100G fabrics. In modern 100 Gbps networks, 64-byte packets arrive every 6.72 nanoseconds. Under such extreme throughput regimes, traditional Intrusion Detection and Prevention Systems (NIDS/NIPS) operating in userspace have encountered catastrophic architectural bottlenecks. Conventional systems such as Snort, Suricata, and Bro/Zeek rely on the standard operating system networking stack. For every arriving frame, the kernel NIC driver must allocate a socket buffer structure (sk_buff), construct socket metadata, traverse network layers, perform memory copies, and trigger context switches across the kernel-userspace boundary. Under volumetric floods, packet capture interfaces (e.g., AF_PACKET, libpcap) suffer severe packet drops at the socket ring buffer, leaving the protected infrastructure vulnerable to denial-of-service and zero-day intrusions.

To circumvent the userspace boundary, the Linux networking community introduced eBPF (Extended Berkeley Packet Filter) and XDP (eXpress Data Path). eBPF provides an in-kernel virtual machine executing custom bytecodes safely in response to kernel events. XDP hooks directly into the network interface card (NIC) driver receive (RX) ring buffer prior to any sk_buff allocation or memory copying. This enables line-rate packet drops (XDP_DROP) or forwarding (XDP_TX, XDP_PASS) in mere nanoseconds. Consequently, researchers have actively sought to migrate machine learning (ML) models directly into the kernel data path.

5.1 Detailed Literature Survey of State-of-the-Art Solutions (2020–2026)

In our foundational literature survey, we analyzed six prominent research methodologies published between 2020 and 2026 addressing eBPF-based intrusion detection. Below, we synthesize their technical architectures, mathematical formulations, and empirical limitations:

  1. Taguchi, Hara, and Kasahara (IEICE Trans. Commun., 2026) [1]: "Unsupervised Real-Time In-Kernel Intrusion Detection System Using Autoencoders and eBPF."
    The authors proposed an unsupervised anomaly detection framework utilizing autoencoders inside eBPF. To eliminate human labeling dependencies, the autoencoder learns normal traffic representations; packets generating high reconstruction errors exceeding a threshold $\theta$ are flagged as anomalies. To overcome eBPF's floating-point prohibition, they adopted Quantization-Aware Training (QAT) to map 32-bit floating-point weights to 8-bit signed integers using Straight-Through Estimators (STE).
    Identified Limitations: The system was evaluated on a per-flow basis, achieving line-rate processing only up to ~203 Kpps; beyond this threshold, CPU capacity depleted rapidly, saturating at 224 Kpps. Crucially, because flow inspection occurred only after complete flow termination, long-lived or persistent connections created critical detection blind spots.
  2. Bachl, Fabini, and Zseby (Computer Networks, 2022) [2]: "A Flow-Based IDS Using Machine Learning in eBPF."
    The authors implemented a flow-based IDS entirely within eBPF using Decision Trees (DTs). Because decision trees do not require iterative loops, they avoid the BPF verifier's loop unwinding complexity. Flows are tracked in a BPF hash map keyed by the 5-tuple. Features include mean absolute deviation computed using 64-bit signed fixed-point integers (16 fractional bits). The in-kernel implementation inspected 152,274 packets per second—21.4% faster than userspace implementations.
    Identified Limitations: While effective for simple decision boundaries, complex non-linear models triggered severe eBPF verifier bounds-checking overheads. Furthermore, tracking standard deviation was impossible due to the lack of square root math in eBPF, limiting feature richness.
  3. Monteiro and Sousa (IEEE NFV-SDN, 2024) [3]: "eBPF Intrusion Detection System with XDP Offload Support (eBPF-LAIN)."
    This work developed a hardware-offloaded IDS targeting port-scan detection. They trained a Random Forest model on the CIDDS-002 dataset and used the emlearn C code generator to expand trees into hardcoded C nested branch statements. The code was partially offloaded to a Netronome Agilio CX SmartNIC using XDP offload driver mode.
    Identified Limitations: The SmartNIC hardware environment was unable to update eBPF map elements dynamically. When LRU maps filled under traffic bursts, classifications were forced back to the host CPU, eliminating hardware acceleration benefits. Additionally, complex multi-tree forests quickly exceeded the BPF verifier's branch complexity limit.
  4. Zhang et al. (IEEE/IFIP DSN, 2024) [4]: "Real-Time Intrusion Detection and Prevention with Neural Network in Kernel Using eBPF."
    Zhang et al. successfully deployed a multi-layer perceptron (MLP) inside the XDP data path. To overcome eBPF's 1-million instruction limit (where even a [6, 32, 32, 2] network would fail verification), the authors pioneered chained tail-calls (bpf_tail_call), decomposing the neural network into modular sub-programs (alternating dense linear matmuls and ReLU activations). They also introduced an "enlargement method" scaling floating-point numbers into 32-bit integers, and a lock-free double-buffered hot-updating mechanism using an nn_index array map to swap between active and idle parameter sets.
    Identified Limitations: To preserve CPU power, neural inference was triggered strictly when a network flow terminated (marked by TCP FIN/RST flags). Consequently, attacks delivered over persistent connections (e.g., HTTP keep-alive, long-lived websockets, slow-rate DoS) completely evaded detection until the socket closed.
  5. Hu et al. (ACM TOCS, 2026) [5]: "EIDS: A Cloud Intrusion Detection System with High Performance and Maintainability."
    EIDS targeted cloud tail latency (where IDS inspection induces up to $17\times$ 99th-percentile overheads). EIDS deployed a tiny eBPF tracer in the guest VM collecting fundamental status (syscalls, PIDs) while deferring complex inspection asynchronously to a dedicated microVM via Virtual Machine Introspection (VMI). Communication utilized per-CPU ring buffers.
    Identified Limitations: Operating asynchronously meant EIDS could not block in-flight network attacks in real time; malicious packets had already executed inside the host before the microVM alerted.
  6. Yu, Hung, and Chou (Computers & Security, 2025) [6]: "Kernel-Level Hidden Rootkit Detection Based on eBPF (HKRD)."
    HKRD deployed eBPF kprobes to detect Direct Kernel Object Manipulation (DKOM) and syscall hijacking in real time, validating task_struct linked list integrity and terminating rogue modules via SIGKILL.
    Identified Limitations: HKRD focused exclusively on host process anomalies rather than line-rate network ingress, and could not directly inspect transport-layer payloads or rate distributions.

5.2 Synthesis of Architectural Research Gaps

A critical synthesis of the state-of-the-art indicates that existing approaches inhabit mutually exclusive design extremes: they either sacrifice classification power for throughput (static XDP rules), sacrifice throughput for classification power (monolithic per-packet ML), compromise security by deferring inspection to flow close (flow-termination ML), or create dangerous exposure windows by delegating detection to asynchronous userspace daemons (ring buffer offloads). This motivates the need for an integrated, multi-tier stateful kernel architecture.

6. Problem Definition

Deploying an intelligent, machine-learning-driven Network Intrusion Detection System directly into the Linux operating system kernel data path poses an acute set of computer systems challenges. In traditional operating systems design, the kernel must guarantee absolute stability, determinism, and safety. A single null-pointer dereference, infinite loop, or unbounded stack access will crash the entire operating system. While eBPF provides a provably safe execution sandbox verified at load time, its safety enforcement mechanisms create five core technical bottlenecks that render naive in-kernel ML infeasible:

The 5 Core Technical Bottlenecks of In-Kernel Machine Learning Intrusion Detection:
  1. Strict BPF Verifier Complexity Limit: eBPF programs cannot exceed 1,000,000 verified instructions. When unrolling neural network matrix multiplications and combining them with L2–L4 packet parsers, the verifier's path-sensitive state exploration triggers complexity rejections, aborting compilation.
  2. Absolute Prohibition of Floating-Point Arithmetic: The Linux kernel prohibits hardware FPU registers (e.g., SSE, AVX) in the networking data path to avoid expensive save/restore context overheads on every interrupt. All neural network forward passes must execute in integer-only fixed-point arithmetic without loss of numerical stability or classification accuracy.
  3. The Line-Rate Throughput Collapse (The Monolithic ML Dilemma): In modern 100 Gbps networks, packets arrive every 6.72 ns. Monolithic architectures that evaluate ML models on every packet incur 450–1,200 ns per packet. Single-core line capacity collapses to ~1.2 Mpps. At 40 Gbps, over 95% of packets are dropped at the NIC driver queue, causing a catastrophic self-inflicted denial of service.
  4. Flow Termination Blindness in Persistent Connections: Systems that defer ML inference until flow termination (TCP FIN/RST) fail to inspect persistent connections, enabling stealthy port scans, data exfiltration, and Slowloris DoS attacks to persist indefinitely without detection.
  5. The Asynchronous Exposure Window: Hybrid user-kernel architectures (e.g., ring buffers) suffer a 5–50 ms reaction delay, allowing over 300,000 attack packets to breach the protected host application before an enforcement rule is installed.

6.1 Mathematical Formulation of the Packet Arrival Budget

Let $R$ denote the physical link line rate (in bits per second) and let $L$ denote the packet length (in bytes). The inter-arrival time $\Delta t_{\text{arrival}}$ between successive frames is formally defined as:

Δtarrival = (L + P + IFG) × 8 / R

where $P = 8\text{ bytes}$ represents the preamble/SFD and $\text{IFG} = 12\text{ bytes}$ is the standard inter-frame gap. For minimum-sized 64-byte Ethernet frames ($L = 64$):

  • At 10 Gbps: $\Delta t_{\text{arrival}} = (64 + 8 + 12) \times 8 / 10^{10} = 672 / 10^{10} = \mathbf{67.2\text{ ns}}$ ($14.88\text{ Mpps}$).
  • At 40 Gbps: $\Delta t_{\text{arrival}} = \mathbf{16.8\text{ ns}}$ ($59.52\text{ Mpps}$).
  • At 100 Gbps: $\Delta t_{\text{arrival}} = \mathbf{6.72\text{ ns}}$ ($148.80\text{ Mpps}$).

If the kernel packet processing latency $T_{\text{proc}}$ exceeds $\Delta t_{\text{arrival}}$, the NIC RX ring buffer fills immediately, resulting in driver-level packet drops:

Drop Rate = max(0, 1 - (Δtarrival / Tproc))

For a monolithic in-kernel ML model requiring $T_{\text{proc}} \approx 800\text{ ns}$, the drop rate at 10 Gbps is $1 - (67.2 / 800) = \mathbf{91.6\%}$, and at 100 Gbps exceeds $\mathbf{99.1\%}$.

6.2 Formal Problem Statement

Given a high-speed network stream arriving at line rate $R \ge 10\text{ Gbps}$ under strict kernel execution constraints (no FPU, $\le 10^6$ verifier instructions, $\le 512\text{ bytes}$ stack per program), design an in-kernel eBPF architecture that:

  1. Maintains an amortized per-packet processing budget $\bar{T}_{\text{proc}} \le 16.8\text{ ns}$, sustaining $\ge 60\text{ Mpps}$ single-core forwarding throughput;
  2. Executes deep neural anomaly detection in integer-only arithmetic with provable scale consistency;
  3. Monitors persistent and transient connections in-flight without waiting for socket closure;
  4. Guarantees sub-microsecond inline quarantine, ensuring zero attack packets breach the host application once flagged; and
  5. Guarantees full verifier compliance across all kernel modules.

7.1 Detailed Analysis of Failure Modes under Line-Rate 100G Conditions

  • Failure Mode 1: The Monolithic Saturation Trap. Monolithic systems evaluate machine learning inference unconditionally on every arriving frame. Even an ultra-compact neural network requires approximately 300 multiply-accumulate operations. When executed on an x86 CPU at 3.0 GHz, memory access to weight tables, activation registers, and bounds checks consume ~350–500 ns. Because 100G line rate demands a packet verdict every 6.72 ns, the CPU core saturates after ~1.2 Mpps. The remaining 98% of line capacity is discarded uninspected by the hardware queue.
  • Failure Mode 2: The Asynchronous Exposure Window. Hybrid architectures place a lightweight eBPF probe at XDP that copies packet metadata into a BPF ring buffer (bpf_ringbuf_output), deferring inference to a user-space daemon. At a typical polling latency of 10 ms, an attacker transmitting at 10 Gbps injects: $$\text{Packets Breached} = 10\text{ ms} \times 14.88\text{ Mpps} = \mathbf{148,800\text{ packets}}$$ At 40 Gbps, over 595,000 attack packets breach the operating system before the userspace daemon writes an entry into the blocking table.
  • Failure Mode 3: The Persistent Connection Blind Spot. Flow-termination models defer evaluation until TCP teardown (`FIN` or `RST` flags). In stealthy denial-of-service attacks such as Slowloris, an attacker opens hundreds of connections and periodically sends tiny byte fragments every few seconds, deliberately never terminating the TCP handshake. Flow-termination IDSes remain completely dormant, permitting attackers to exhaust server sockets indefinitely.

8. New Suggestion for Improvement: The AHHS-IDS Framework

To break the fundamental compromises of prior art, we proposed and implemented the Adaptive Hybrid Hardware-Software Intrusion Detection System (AHHS-IDS). AHHS-IDS is structured upon the principle of Hierarchical Stateful Amortization, establishing a three-tiered processing pipeline residing entirely inside the Linux kernel data path:

8.1 The 3-Tier Pipeline Architecture

  • Tier 1: Stateless Decision Tree Pre-Filter: Positioned directly at driver ingress. It executes a compiled branchless decision tree (`bpf/tier1_tree.h`) evaluating 5-tuple protocol metrics. Verified benign traffic (HTTP/HTTPS, DNS, NTP) is passed immediately (`XDP_PASS`), while confirmed threat signatures (Telnet 23, Backdoors 4444, Mirai 2323) are dropped instantly (`XDP_DROP`). Tier 1 resolves ~90% of raw ingress volume in 11.8 ns without hash map lookups.
  • Tier 2: Stateful LRU Sliding Window Tracking: Ambiguous traffic (the remaining 10%) is diverted to Tier 2. An eBPF LRU hash map (`flow_lru_map`, 65,536 entries) maintains running statistics for active connections. By aggregating traffic over sliding windows of 100 packets or 1.0 second, Tier 2 inspects traffic in-flight, eliminating persistent connection blind spots.
  • Tier 3: Deep Quantized Neural Autoencoder: When a window completes, 8 statistical features are compressed via a fixed-point logarithm (`log2q3`) and passed to Tier 3. An integer-quantized neural autoencoder ($8 \to 16 \to 4 \to 16 \to 8$, 428 parameters, 592 bytes) evaluates reconstruction error across 4 chained tail-calls (`bpf_tail_call`). Because Tier 3 executes once per 100 ambiguous packets, its 342.0 ns execution latency is amortized to an empirical 3.42 ns per ambiguous packet.

8.2 In-Kernel Quantization & Mathematical Error Alignment

To eliminate floating-point arithmetic without degrading detection accuracy, AHHS-IDS employs Quantization-Aware Training (QAT) with Straight-Through Estimators (STE). The autoencoder compresses an 8-dimensional input into a 4-neuron bottleneck representation before linear reconstruction ($8 \to 16 \to 4 \to 16 \to 8$).

A critical mathematical vulnerability in prior quantized autoencoders is scale mismatch: if input vector $x$ and reconstructed output vector $y$ have different quantization scaling factors, the sum of squared errors $\sum (x_i - y_i)^2$ is mathematically undefined. In AHHS-IDS, we enforce a strict symmetric scale constraint: the Layer 4 output scale is explicitly fixed to match the input scale:

sio = 2-5 = 1 / 32   &implies;   xq, i = clamp(xi - zpi, -128, 127)   &implies;   err = ∑i=07 (xq, i - yi)2

Input features are centered using zero-points ($zp_i$) derived from benign training traffic means. Dense layer requantization rescales accumulators via integer multipliers $M$ with a 24-bit arithmetic shift ($\text{AHHS\_REQUANT\_SHIFT} = 24$), ensuring bit-exact scale consistency inside the kernel:

M = round(224 × (sin × sw / sout))   &implies;   v = ((acc × M) + 223) >> 24

8.3 Immediate Dynamic Fast-Path Quarantine

When Tier 3 detects that reconstruction error exceeds the calibrated anomaly threshold ($\text{err} > \theta = 58$), the triggering packet is dropped immediately (`XDP_DROP`). Simultaneously, the 5-tuple is inserted into an in-kernel hash map (`ahhs_blocklist`, 16,384 entries) with a 60-second time-to-live ($t_{\text{expire}} = \text{ktime} + 60\text{ s}$).

Subsequent packets matching the quarantined 5-tuple are intercepted at the Tier 1 ingress fast-path (~12 ns) and dropped immediately, completely bypassing Tier 2 and Tier 3 processing. Once the 60-second quarantine window elapses, the entry expires automatically, allowing legitimate connections to recover without administrator intervention.

8.4 Zero-Downtime Double-Buffered Hot-Swapping

To accommodate shifting network attack vectors and baseline drift, model parameters are stored in a double-buffered BPF array map (`ahhs_model_map`, 2 slots $\times$ 592 bytes). A userspace coordinator writes updated parameters into the idle slot and atomically toggles a single-entry index map (`ahhs_nn_index`), updating the active neural network with zero downtime and zero packet drops:

active_slot = ahhs_nn_index[0] ⊕ 1   &implies;   ahhs_nn_index[0] = active_slot

8.5 Mathematical Amortization Proof

Let $\alpha$ represent the fraction of traffic resolved statelessly at Tier 1 ($\alpha \approx 0.90$), and let $(1 - \alpha)$ represent the fraction of ambiguous traffic requiring stateful tracking ($\approx 0.10$). Let $W$ denote the sliding window size ($W = 100$). The average in-kernel processing latency per packet $\bar{T}_{\text{AHHS}}$ is rigorously derived as:

T̄AHHS = α × TTier1 + (1 - α) × (TTier2 + (1 / W) × TTier3)

Substituting our empirically measured kernel latencies ($T_{\text{Tier1}} = 11.8\text{ ns}$, $T_{\text{Tier2}} = 45.0\text{ ns}$, $T_{\text{Tier3}} = 342.0\text{ ns}$, $W = 100$):

T̄AHHS = 0.90 × 11.8 + 0.10 × (45.0 + 3.42) = 10.62 + 4.842 = 15.46 ns / packet

Accounting for driver-level RX DMA overheads (~0.99 ns), the net ingress latency is 16.45 ns/packet, satisfying the line-rate arrival budget for 40 Gbps and sustaining 60.7 Mpps on a single core.

9. Implementation Details

AHHS-IDS was implemented as a production-grade Linux kernel security pipeline in modern C (compiled targeting BPF architecture via Clang/LLVM 18) and Python 3. Below, we detail the core implementation mechanics across kernel data structures, fixed-point math, and userspace control systems:

9.1 Linux Kernel BPF Map Architecture

To guarantee zero dynamic memory allocation and strict cache locality, AHHS-IDS allocates 7 dedicated BPF maps at initialization:

9.2 Fixed-Point Logarithm Feature Compression (`log2q3`)

Traffic statistics span orders of magnitude (from single-packet SYN probes to gigabyte streaming transfers). To compress inputs into uniform `uint8` ranges $[0, 255]$ without floating-point math, we implemented a custom fixed-point base-2 logarithm with 3 fractional bits (Q5.3 format):

e = ⌊ log2(x + 1) ⌋,     frac = ⌊ (x + 1) / 2e - 3 ⌋ mod 8,     log2q3(x) = (e ≪ 3) | frac

The 8 extracted features mapped from each 100-packet window are:

  1. Feature 0 (Packet Count): $x_0 = \text{log2q3}(n)$ — number of packets in the window ($n \le 100$).
  2. Feature 1 (Mean Packet Length): $x_1 = \text{log2q3}(\text{bytes} / n)$ — average frame payload size.
  3. Feature 2 (Maximum Packet Length): $x_2 = \text{log2q3}(\text{len}_{\max})$ — maximum observed frame size.
  4. Feature 3 (Length Variance): $x_3 = \text{log2q3}(\mathbb{E}[X^2] - (\mathbb{E}[X])^2)$ — dispersion of packet sizes.
  5. Feature 4 (Mean Inter-Arrival Time): $x_4 = \text{log2q3}(\text{IAT}_{\text{sum}} / (n - 1))$ in μs.
  6. Feature 5 (Maximum Inter-Arrival Time): $x_5 = \text{log2q3}(\text{IAT}_{\max})$ in μs.
  7. Feature 6 (Total Window Bytes): $x_6 = \text{log2q3}(\text{bytes})$ — aggregate volume transferred.
  8. Feature 7 (TCP SYN Ratio): $x_7 = (N_{\text{SYN}} \times 255) / n$ — proportion of SYN flags in window.

9.3 Chained In-Kernel Tail-Call Execution

Each dense layer computes 32-bit signed integer accumulators, followed by scaled requantization. The C implementation utilizes unrolled matrix multiplications with explicit bounds checks:

/* In-kernel Dense Layer Requantization Core (bpf/ahhs_common.h) */ static __always_inline void dense_requant(const int8_t *in, int8_t *out, const int8_t *w, const int32_t *b, int32_t M, int in_d, int out_d, int8_t lo) { #pragma unroll for (int o = 0; o < out_d; o++) { int32_t acc = b[o]; #pragma unroll for (int i = 0; i < in_d; i++) { acc += ((int32_t)w[o * in_d + i]) * ((int32_t)in[i]); } /* Fixed-point scale multiplication with 24-bit arithmetic shift */ int64_t scaled = ((int64_t)acc * (int64_t)M) + (1 << (AHHS_REQUANT_SHIFT - 1)); int32_t v = (int32_t)(scaled >> AHHS_REQUANT_SHIFT); out[o] = (int8_t)(v < lo ? lo : (v > 127 ? 127 : v)); } }

Layers 1, 2, and 3 use $\text{lo} = 0$ (in-kernel ReLU), while Layer 4 uses $\text{lo} = -128$ (linear reconstruction). Sub-programs pass activations by ping-ponging between scratch->buf_a and scratch->buf_b, eliminating stack spilling and staying within the 512-byte eBPF stack limit:

/* Tier 3 Program 1: Layer 1 Dense (8 -> 16) + Tail Call (bpf/xdp_ahhs_tier3.c) */ SEC("xdp") int ahhs_t3_l1(struct xdp_md *ctx) { struct ahhs_scratch *s = bpf_map_lookup_elem(&ahhs_scratch_map, &zero); if (!s) return XDP_PASS; const struct ahhs_model_weights *w = get_active_model(); if (!w) return XDP_PASS; /* Center inputs with zero points: in_vec[i] = clamp(raw[i] - zp[i], -128, 127) */ #pragma unroll for (int i = 0; i < 8; i++) { int32_t val = (int32_t)s->in_raw[i] - (int32_t)w->l1_zp[i]; s->buf_a[i] = (int8_t)(val < -128 ? -128 : (val > 127 ? 127 : val)); } dense_requant(s->buf_a, s->buf_b, w->w1, w->b1, w->M1, 8, 16, 0); /* ReLU */ bpf_tail_call(ctx, &ahhs_t3_prog_array, 1); /* Dispatch Layer 2 */ return XDP_PASS; /* Fail-open fallback */ }

9.4 Verifier Safety Annotations

To pass the Linux eBPF verifier across kernel versions 5.15 through 6.8, several critical safety patterns were implemented:

  • Null Pointer Assertions: Every map lookup return pointer is immediately verified with an explicit if (!ptr) return XDP_PASS; guard before any member dereference.
  • Bounded Loop Unrolling: All inner loops over input and output dimensions are annotated with #pragma unroll, eliminating backward jump instructions and guaranteeing $O(1)$ loop execution.
  • Constant Array Indexing: Array lookups into parameter tables are guaranteed to be compile-time constants or bounded integers masked with bitwise AND operators (`idx & 0x0F`).

10. Results & Performance Evaluation

10.3 In-Flight Detection Dynamics: Mitigating Slowloris and Port-Scanning In-Flight

The empirical findings in Table 3 highlight the superiority of AHHS-IDS's sliding-window architecture over prior flow-termination IDSes:

  • PortScan Detection Dynamics: Port scanning attacks transmit rapid sequences of TCP SYN packets across hundreds of closed destination ports. Because Tier 1 identifies unknown destination ports as ambiguous, flows are routed to Tier 2. In Tier 2, Feature 7 ($N_{\text{SYN}} / n$) saturates at 255 while Feature 3 (length variance) drops to 0. When evaluated by Tier 3, reconstruction error surges to over 16,000 (≫ 58), achieving a 100.00% detection rate. The scanning IP is immediately placed in `ahhs_blocklist`, dropping subsequent probes in 11.8 ns.
  • Slowloris In-Flight Detection Dynamics: Slowloris DoS attacks open persistent TCP connections and transmit partial HTTP headers at delayed intervals (e.g., every 5–15 seconds), deliberately avoiding TCP termination. Under prior flow-termination IDSes (e.g., Zhang et al., DSN 2024), these connections are never inspected while active. In AHHS-IDS, the sliding window timeout ($> 1.0\text{ s}$) forces feature evaluation in-flight. Abnormal inter-arrival times (Feature 4 and 5) produce reconstruction errors between 78 and 1,944, successfully detecting 70.14% of Slowloris flows while connections remain open.
  • Benign Traffic Preservation: Held-out Monday benign traffic yielded an empirical False Positive Rate (FPR) of 9.81% (206 false alarms across 2,100 windows). Most false alarms were triggered by bursty large file transfers with atypical packet length variance.

10.5 In-Kernel Resource Footprint & Verifier Compliance

AHHS-IDS satisfies all Linux kernel operational constraints:

  • Verifier Compliance: Across all 4 sub-programs, the maximum instruction count was 142 instructions, representing less than 0.015% of the 1,000,000 instruction limit. All verification checks passed in under 4 ms.
  • Memory Footprint: The entire system state—including `flow_lru_map` (5.76 MB), `ahhs_blocklist` (393 KB), parameter array (1.18 KB), and telemetry arrays—occupies exactly 7.2 MB. This fits entirely within the L3 cache of modern server CPUs (typically 32–128 MB), completely eliminating DRAM memory access latency.
  • Stack Budget: Maximum stack consumption observed across any sub-program was 192 bytes, well within the 512-byte eBPF stack limit.

10.6 Bit-Exact Golden Trace Verification

To verify mathematical integrity between offline Python training and kernel C execution, 240 stratified golden test vectors were injected into `bpf/xdp_ahhs_tier3.c:ahhs_t3_selftest()` via `BPF_PROG_TEST_RUN`. 240 out of 240 vectors (100.0%) matched the reference integer model bit-for-bit with zero discrepancies in reconstruction error or classification verdict.

11. Conclusions & Future Work

This term project successfully designed, implemented, and benchmarked AHHS-IDS, proving that deep, stateful neural network anomaly detection can be executed entirely inside the Linux kernel data path without hardware floating-point registers and without violating strict eBPF verifier safety constraints.

By introducing hierarchical stateful amortization—pairing an 11.8 ns stateless decision tree pre-filter with a 45 ns LRU sliding window tracker and a 4-program chained quantized autoencoder—AHHS-IDS resolves the fundamental in-kernel IDS dilemma:

  • It achieves 60.7 Mpps line-rate throughput, eliminating the line-rate collapse of monolithic per-packet neural networks.
  • It inspects active traffic in-flight over 100-packet windows, eliminating the persistent connection blind spots of flow-termination IDSes.
  • It enforces sub-microsecond in-kernel dynamic blocklisting, eliminating the massive exposure gap of hybrid ring-buffer offloads.
  • When evaluated on the official CIC-IDS-2017 benchmark corpus (1,210,000 packets), it delivered an 85.07% detection rate (100.00% on PortScan, 70.14% on DoS Slowloris) with an ROC-AUC of 0.9567, 100% bit-exact kernel parity, and a compact 7.2 MB memory footprint residing completely within CPU L3 cache.

Future research directions include offloading Tier 1 decision trees to hardware SmartNICs (e.g., Netronome Agilio CX or NVIDIA BlueField DPUs) and developing an automated control-plane daemon for online unsupervised parameter retraining based on runtime drift detection.
